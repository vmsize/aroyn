# Contributing

Before proposing a change, open an issue describing the problem and the component affected. Keep changes focused, explain how to reproduce the issue, and include the checks you ran. Never include credentials, user records, payloads, or production configuration in an issue or pull request.

Fork the repository and submit a pull request against `main`. Explain the change, its verification and any remaining limitations. Use synthetic fixtures for tests. Report security vulnerabilities privately as described in [SECURITY.md](SECURITY.md).

Contributions to the original software are made under the repository's MIT license. Keep third-party notices and the separate brand-asset terms intact.
